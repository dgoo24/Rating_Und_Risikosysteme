# Data dictionary

All data in this prototype is **synthetic**. Five fictional Sparkassen-like
institutions (SSK001–SSK005) report nine quarterly snapshots from
2024-09-30 to 2026-09-30. No real institution, customer, employee or
portfolio is represented.

## Landing zone (source layer)

`data/synthetic/landing/` — generated by `python -m synthetic_data.generate_data`
(seed 42). The format mix is deliberate: it exercises the mapping layer.

| Bank | Files | Format | Quirks |
|---|---|---|---|
| SSK001 | `sparkasse_a_*.csv` (4) | CSV | canonical English column names |
| SSK002 | `sparkasse_b_*.xlsx` (4) | Excel | German column names, sheets `Portfolio`, `Ratings`, `Sicherheiten`, `Zahlungen` |
| SSK003 | `sparkasse_c_*.csv` (4) | CSV | semicolon-separated, code-oriented fields, German number format (`1.234,56`) |
| SSK004 | `sparkasse_d_*` (mixed, 4) | Excel/CSV | local German names |
| SSK005 | `sparkasse_e_source.duckdb` | DuckDB | tables `portfolio_export`, `rating_history_export`, `collateral_export`, `recovery_export` |

Each bank exports four datasets: exposures, rating history, collateral,
recovery cashflows. `data/synthetic/landing/institutions.csv` carries the
institution master. The generator also injects deliberate quality defects
(missing IDs, invalid grades, wrong currencies, duplicates, stale valuations,
future dates …) so the quality engine has something to catch; the manifest
`data/synthetic/master/generation_manifest.json` lists them.

## Canonical dataset schemas (curated layer)

Curated tables live in `data/processed/risk_portfolio.duckdb`. Column names
are identical across all source dialects; mapping happens in
`ingestion/source_mapping.py` + `etl/transformations.py`.

### exposures (one row per exposure and quarterly snapshot)

| Column | Type | Meaning |
|---|---|---|
| `exposure_id` | VARCHAR | Stable exposure identifier, e.g. `EXP001` |
| `bank_id` | VARCHAR | Reporting institution, `SSK001`–`SSK005` |
| `customer_id` | VARCHAR | Fictional customer reference |
| `snapshot_date` | DATE | Quarterly reporting snapshot (business key with `exposure_id`) |
| `product_type` | VARCHAR | e.g. `CORPORATE_LOAN`, `MORTGAGE`, `OVERDRAFT` |
| `industry_sector` | VARCHAR | Sector of the borrower |
| `region` | VARCHAR | Region of the borrower |
| `rating_grade` | VARCHAR | Master rating on the configured scale |
| `exposure_at_default` | DOUBLE | EAD in EUR |
| `outstanding_balance` | DOUBLE | Outstanding amount in EUR |
| `currency` | VARCHAR | Reporting currency (EUR only in the prototype) |
| `origination_date` | DATE | Contract start |
| `maturity_date` | DATE | Contract maturity |
| `default_flag` | BOOLEAN | Observed default indicator at the snapshot |
| `default_date` | DATE | Observed default date (present iff defaulted) |
| `batch_id` | VARCHAR | Provenance: the ingestion batch that loaded the row |

### rating_history (one row per exposure, bank and observation date)

| Column | Type | Meaning |
|---|---|---|
| `exposure_id` | VARCHAR | Exposure reference |
| `bank_id` | VARCHAR | Owning institution |
| `observation_date` | DATE | Rating observation date (business key with `exposure_id`) |
| `rating_grade` | VARCHAR | Rating on the A–F scale at that date |
| `batch_id` | VARCHAR | Provenance |

### collateral (one row per collateral valuation)

| Column | Type | Meaning |
|---|---|---|
| `collateral_id` | VARCHAR | Collateral identifier, e.g. `COL001` |
| `exposure_id` | VARCHAR | Secured exposure |
| `bank_id` | VARCHAR | Owning institution |
| `collateral_type` | VARCHAR | `REAL_ESTATE`, `FINANCIAL_COLLATERAL`, `OTHER` |
| `collateral_value` | DOUBLE | Valuation in EUR |
| `valuation_date` | DATE | Valuation date (business key with `collateral_id`) |
| `currency` | VARCHAR | EUR |
| `batch_id` | VARCHAR | Provenance |

### recovery_cashflows (one row per recovery payment)

| Column | Type | Meaning |
|---|---|---|
| `cashflow_id` | VARCHAR | Cashflow identifier, e.g. `CF001` |
| `exposure_id` | VARCHAR | Defaulted exposure the payment belongs to |
| `bank_id` | VARCHAR | Owning institution |
| `payment_date` | DATE | Payment date |
| `recovery_amount` | DOUBLE | Recovered amount in EUR |
| `recovery_type` | VARCHAR | e.g. `PROCEEDS_SALE`, `COLLATERAL_LIQUIDATION` |
| `adjustment_reason` | VARCHAR | Required when aggregate recoveries exceed EAD |
| `batch_id` | VARCHAR | Provenance |

### institutions (reference master)

`bank_id`, `bank_name`, `region`, `peer_group` for the five fictional banks.
Peer groups: `PG_URBAN` = SSK001, SSK003, SSK005; `PG_REGIONAL` = SSK002, SSK004.

## Audit and staging tables

| Table | Grain | Purpose |
|---|---|---|
| `pipeline_runs` | one ETL run | run status, batch/row counters |
| `ingestion_batches` | one ingested file | source system, file hash, raw archive path, rows received/valid/rejected, quality score |
| `staging_*` (4 tables) | one raw row | mirrors the source including duplicates, for audit |
| `dq_rule_catalog` | one rule | the 63 seeded quality rules (see `docs/data_quality_rules.md`) |
| `quality_results` | one finding | rule violations with record ID, field, failed value |
| `quarantine_records` | one rejected record | full record JSON + reasons; nothing is silently dropped |
| `report_log` | one generated artefact | report type, format, path, status, data version, contributing batch IDs |
| `distribution_log` | one simulated distribution | channel/recipient manifest (no real sending) |

## Reference values (config/)

- Rating scale: `A B C D E F` (A best). Investment grade = A–B.
- PD 12M by grade: A 0.1%, B 0.3%, C 0.8%, D 2%, E 5%, F 12% (fictional).
- Collateral haircuts: REAL_ESTATE 20%, FINANCIAL_COLLATERAL 5%, OTHER 40%.
- Stale valuation threshold: 3 years (WARNING).
- Default observation window: 12 months before the reporting date.
- Currency: EUR only.

## Record ID conventions

- `exposures` → `exposure_id`
- `rating_history` → `exposure_id@observation_date`
- `collateral` → `collateral_id`
- `recovery_cashflows` → `cashflow_id`
- Missing key components fall back to `MISSING_ID` / `MISSING_DATE` so
  findings remain traceable to a snapshot.
